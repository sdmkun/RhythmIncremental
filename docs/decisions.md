## 決定済み

### D-1. ゲームの3本柱【2026-07-22 確定】

ジャンル変化 / リアルタイムFX / プレステージ。詳細は [vision.md](vision.md)。
機能の取捨選択はこの3つへの寄与で判断する。

### D-2. スキルツリーは Yggdrasil を使う【2026-07-22 実装済み】

`scenes/skill_tree/skill_tree.gd` で稼働中。
`SkillData` を唯一の真実とし、Yggdrasil は視覚グラフとノード状態のみを担当。
購入は必ず `GameState.buy_upgrade()` を通す。

Yggdrasil 標準のクリック処理（1レベル取ったら再購入不可）は切断済みで、
独自ハンドラ `_on_node_pressed()` が購入を駆動している。
**排他スキルの実装はここに足す** → [progression-design.md](progression-design.md)。

### D-3. PDJE の Judge/譜面DB は当面採用しない【2026-07-22 保留】

PDJE の判定モジュールは**独自DBで譜面を再構築する必要**があり
（`PDJE_EDITOR_ARG`、rail-id デバイスマッピング、毎フレームの入力ポンプ）、
既存の `demo_chart.json` を直接食わせる手段が文書化されていない。

→ **判定は GDScript のまま据え置く。**

ただしこれは **PDJE を使わないという意味ではない**（D-4 参照）。

### D-4. PDJE は「音声用途」として採用する方向【2026-07-22 提案・要承認】

D-3 の調査後に判明した重要事項として、PDJE は音声側の API が
このゲームの要求とほぼ一致している:

- `MusPanelWrapper.SetMusic(title, on/off)` — レイヤーON/OFF（柱1）
- `getFXHandle()` + `SetFXArg()` — リアルタイムFX 18種（柱2）
- `PDJE_AI` Beat This — 任意音源からビート抽出（AI生成音源の自動譜面化）

**音声（Core / MusPanel / FX）だけ採用し、判定と譜面DBは採用しない**
という分離が可能。柱1・柱2の実現手段としては現状これが最有力。

→ 詳細は [audio-design.md](audio-design.md)。

ユーザー: 「まだ決めていない。ループ音源ファイルを必要なだけ渡すことはできる。
Gemini API の音楽生成が使えたら一番嬉しい」

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A | ループ音源を手で用意 | 確実。出荷ラインとして堅い |
| B | Gemini(Lyria系) で実行時生成 | 柱1と相性抜群だが**リズムゲームの中核には危険**（非決定的・要ネットワーク） |

**Claude の推奨: 案C（または案A）で出荷ラインを作り、案Bはサブモードとして後回し。**

→ トレードオフの詳細は [audio-design.md](audio-design.md#音源をどう調達するか未決定)。

### Q-2. 譜面フォーマットを拍ベースに移行するか

現在は秒指定（`{"time": 1.50, "lane": 1}`）。
ジャンルによって BPM が変わるなら秒指定は破綻する。

→ **ジャンル変化の実装前に決める必要がある。**
BPM 固定で進めるなら当面は現状維持でよい。

### Q-3. スロット数とジャンル数

[progression-design.md](progression-design.md) では 5スロット × 4ジャンル を仮置きしている。
必要な音源数 = スロット数 × ジャンル数 なので、
**Q-1 の調達方法が決まらないと確定できない。**

### Q-4. 排他の粒度

- スロット単位で完全排他（Drums は1ジャンルのみ）か
- 曲全体で1ジャンル固定か
- 混成を許してボーナスを付けるか

【提案】混成を許すほうがビルドの探索が楽しい。→ [progression-design.md](progression-design.md)
